# Mexamen — План реализации (plan.md)

> Компаньон `spec.md`. Здесь — **как** и **в каком порядке**. Каждая задача маленькая, независимо проверяемая и оставляет проект в рабочем состоянии. Делаем по одной задаче за раз, чужой код не рефакторим.

**Формат задачи:** Цель · Описание · Ожидаемые файлы · Зависимости · Definition of Done · Ручная проверка.

**Стратегия.** Фаза A — данные (без них ничего нет). Фаза B — каркас приложения. Фаза C — domain: retrieval + fallback (квиз уже играбелен оффлайн). Фаза D — LLM-дистракторы поверх. Фаза E — UI-полировка и приёмка. Вертикальный срез «играбельный квиз» появляется в конце фазы C, LLM — деталь качества, а не блокер.

## Фаза A — Оффлайн-пайплайн данных

### Задача A1 — Скрейпер гида
- **Цель:** `tools/scrape_guia.py` превращает https://ruspansky.com/guia-de-estudios/ в `questions.json`.
- **Описание:** Python (requests + BeautifulSoup). Скачать страницу, распарсить 13 разделов, извлечь пары «вопрос → ответ» (~800). Чистка: обрезка пробелов, нормализация тире/кавычек, отсев пустых и дублей. Формат: `[{"id": 1, "section": "...", "question": "...", "answer": "..."}]`. Сохранить сырой HTML рядом (кэш, чтобы не дёргать сайт повторно).
- **Файлы:** `tools/scrape_guia.py`, `tools/requirements.txt`, `tools/out/questions.json`.
- **Зависимости:** нет.
- **DoD:** `questions.json` содержит ≥ 700 записей, все 13 разделов представлены; спот-чек 10 случайных записей — вопрос и ответ совпадают с сайтом.
- **Проверка:** `python tools/scrape_guia.py`; глазами посмотреть JSON и сверить выборочно с сайтом.

### Задача A2 — Эмбеддинги
- **Цель:** `tools/build_embeddings.py` пишет `embeddings.bin` для всех вопросов.
- **Описание:** По паттерну `AI-Playground/week_5_RAG/embedder.py`: локальный Ollama, `nomic-embed-text` (768-dim). Эмбеддится строка «вопрос + ответ». Выход — бинарный файл: заголовок (count, dim), затем float32 little-endian подряд в порядке id. Скрипт идемпотентен, показывает прогресс, падает с понятной ошибкой если Ollama не запущен.
- **Файлы:** `tools/build_embeddings.py`, `tools/out/embeddings.bin`.
- **Зависимости:** A1; запущенный Ollama с `nomic-embed-text`.
- **DoD:** размер файла = 8 + count×768×4 байт; count равен числу записей в JSON; скрипт-самопроверка: cosine(вектор вопроса о столице Jalisco, вектор вопроса о столице Nuevo León) заметно выше, чем с вопросом о литературе.
- **Проверка:** запустить скрипт, увидеть прогресс и итоговую самопроверку top-K соседей для 2–3 вопросов.

## Фаза B — Каркас приложения

### Задача B1 — Bootstrap Compose Multiplatform
- **Цель:** Пустое CMP-приложение (только Android-таргет) собирается и запускается.
- **Описание:** Сгенерировать проект (KMP wizard / шаблон): Kotlin 2.x, Compose Multiplatform, Material 3, `commonMain`/`androidMain`, minSdk 26. Экран-заглушка «Mexamen». Версии — в `gradle/libs.versions.toml`. `.gitignore`, `git init`.
- **Файлы:** `settings.gradle.kts`, `build.gradle.kts`, `gradle/libs.versions.toml`, `composeApp/**`, `.gitignore`.
- **Зависимости:** нет (параллельно фазе A).
- **DoD:** `./gradlew :composeApp:assembleDebug` зелёный; APK ставится на эмулятор, показывает заглушку.
- **Проверка:** установить APK, увидеть экран.

### Задача B2 — Ассеты + загрузка датасета
- **Цель:** Приложение читает `questions.json` и `embeddings.bin` из ресурсов.
- **Описание:** Скопировать выход фазы A в `composeApp/src/commonMain/composeResources/files/`. `QuestionRepository` в `commonMain`: ленивая загрузка JSON (kotlinx.serialization) и бинарных векторов (parsing заголовка, FloatArray). Никакой БД — всё в памяти.
- **Файлы:** `…/data/QuestionRepository.kt`, `…/data/QuestionEntry.kt`, ресурсы, тест `QuestionRepositoryTest`.
- **Зависимости:** A1, A2, B1.
- **DoD:** unit-тест: загрузилось ≥ 700 записей, у каждой есть вектор длины 768, id согласованы.
- **Проверка:** `./gradlew :composeApp:testDebugUnitTest`.

## Фаза C — Domain: retrieval + играбельный квиз (без LLM)

### Задача C1 — VectorStore + выбор вопросов
- **Цель:** Косинусный top-K и выбор 10 случайных вопросов.
- **Описание:** `VectorStore.topK(id, k)` — полный перебор cosine по 800 векторам, исключая сам вопрос. `QuestionPicker.pick(10)` — случайные вопросы, ≤ 2 на раздел (FR-2), инжектируемый `Random` для тестов. Чистый `commonMain`.
- **Файлы:** `…/domain/VectorStore.kt`, `…/domain/QuestionPicker.kt`, тесты.
- **Зависимости:** B2.
- **DoD:** тесты: topK возвращает k результатов без самого вопроса, отсортированы по убыванию близости; picker с фиксированным seed детерминирован и соблюдает лимит по разделам.
- **Проверка:** тесты зелёные; в тесте распечатать соседей 3 вопросов — семантика осмысленная.

### Задача C2 — Fallback-дистракторы + сборка квиза
- **Цель:** Полный `QuizQuestion` без LLM: варианты = ответы 3 ближайших соседей.
- **Описание:** `RagFallback.distractors(entry, neighbors)` — ответы top-соседей, дедупликация (case/accent-insensitive, не равны правильному ответу), добор следующими соседями. `BuildQuizUseCase` собирает 10 `QuizQuestion` (перемешивание вариантов, `source = FALLBACK`).
- **Файлы:** `…/domain/RagFallback.kt`, `…/domain/BuildQuizUseCase.kt`, тесты.
- **Зависимости:** C1.
- **DoD:** тесты: всегда ровно 4 уникальных варианта, верный присутствует, позиция верного равномерно случайна (seed-тест).
- **Проверка:** тесты зелёные.

### Задача C3 — UI квиза (вертикальный срез)
- **Цель:** Играбельный квиз на fallback-дистракторах.
- **Описание:** `QuizViewModel` (StateFlow: Loading / Question(n, options) / Result). Экраны: Home («Начать квиз»), Quiz (вопрос, 4 кнопки-варианта, подсветка верно/неверно после выбора, автопереход), Result (X/10, разбор, «ещё раз»). Material 3, простая навигация (state-driven, без Navigation-библиотеки).
- **Файлы:** `…/ui/QuizViewModel.kt`, `…/ui/HomeScreen.kt`, `…/ui/QuizScreen.kt`, `…/ui/ResultScreen.kt`, `App.kt`.
- **Зависимости:** C2.
- **DoD:** на эмуляторе проходится полный квиз 10/10 без сети; повторный запуск — другие вопросы.
- **Проверка:** пройти квиз руками в авиарежиме эмулятора.

## Фаза D — LLM-дистракторы

### Задача D1 — LlmProvider + DeepSeekProvider
- **Цель:** Рабочий вызов DeepSeek из `commonMain`.
- **Описание:** `interface LlmProvider { suspend fun complete(system: String, user: String): String }`. `DeepSeekProvider` — Ktor Client, `POST https://api.deepseek.com/v1/chat/completions`, `deepseek-chat`, temperature 0.7, timeout 30 с (паттерн `test_deepseek.py`). Ключ: `local.properties` → `BuildConfig` → expect/actual в `commonMain`. Без ключа провайдер сразу кидает типизированную `LlmUnavailable`.
- **Файлы:** `…/llm/LlmProvider.kt`, `…/llm/DeepSeekProvider.kt`, gradle-проводка ключа, тест с Ktor MockEngine.
- **Зависимости:** B1.
- **DoD:** MockEngine-тест: корректный запрос/парсинг ответа; интеграционный smoke (ручной, с реальным ключом) возвращает текст.
- **Проверка:** временный smoke-вызов с реальным ключом из теста/лога.

### Задача D2 — Промпт + парсинг + интеграция в квиз
- **Цель:** Дистракторы от LLM с RAG-контекстом, батчем на 10 вопросов.
- **Описание:** `DistractorGenerator`: собирает system-промпт (составитель экзамена, испанский, JSON-only) + user-JSON из 10 вопросов с RAG-контекстом (FR-4); парсит ответ (FR-5); поэлементная валидация; дыры — из `RagFallback`. `BuildQuizUseCase` переключается: LLM-путь → при ошибке целиком fallback (FR-6). `source` проставляется честно.
- **Файлы:** `…/llm/DistractorGenerator.kt`, `…/llm/PromptBuilder.kt`, обновление `BuildQuizUseCase`, тесты (валидный ответ, кривой JSON, частично невалидный, полный отказ).
- **Зависимости:** C2, D1.
- **DoD:** тесты на все 4 сценария зелёные; с реальным ключом квиз получает LLM-дистракторы ≥ 8/10 вопросов.
- **Проверка:** пройти квиз с ключом — дистракторы правдоподобные, на испанском; выдернуть сеть — квиз работает (fallback).

## Порядок и параллельность

```
A1 ─► A2 ─┐
          ├─► B2 ─► C1 ─► C2 ─► C3 ─► E1 ─► E2
B1 ───────┘              └──────► D2 ─┘
B1 ─► D1 ────────────────────────┘
```

Риски: (1) разметка ruspansky.com может парситься неровно → A1 закладывает чистку и спот-чек; (2) DeepSeek может вернуть неровный JSON → FR-5/D2 валидируют поэлементно; (3) без Ollama нет эмбеддингов → фаза A выполняется один раз, артефакты коммитятся.
