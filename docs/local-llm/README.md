# День 4. Local Boost — локальная LLM как код-ассистент

Ollama + Continue.dev в Cursor, CPU-only ноутбук. Те же задачи, что и у облачного ассистента (Claude Code) в Днях 1–2. Прогоны 2026-10-23, n = 1 на конфигурацию — наблюдение, не статистика.

## 1. Железо и выбор моделей

| | |
|---|---|
| CPU | AMD Ryzen 5 3550H, 4 ядра / 8 потоков, AVX2 |
| RAM | 14 GiB доступно, ~6–8 GiB свободно при открытом Cursor |
| GPU | Radeon Vega 8 (интегрированная) → инференс на CPU |
| Движок | Ollama 0.34 (snap), `localhost:11434` |

| Модель | Размер (Q4) | Роль | Почему |
|---|---|---|---|
| `qwen2.5-coder:1.5b` | 1.0 GB | **автокомплит** (FIM) + чат | единственная кодовая модель, дающая подсказку за ~3 с на CPU |
| `qwen2.5:3b` | 1.9 GB | чат / агент / edit | лучшее следование инструкциям из того, что помещается; уже была установлена |
| `qwen2.5-3b-mexamen` | (= qwen2.5:3b) | **лучшая связка** | Modelfile: `repeat_penalty 1.15`, `repeat_last_n 256`, `num_ctx 8192` |
| `qwen3:4b` | 2.5 GB (5.1 GB с ctx 16k) | только бенчмарк | лучший ответ, но 20 мин на ответ — непригодна для IDE |

Отвергнуты: 7B (`qwen2.5-coder:7b`, 4.7 GB) — по решению пользователя, тяжело рядом с Gradle/Cursor; `deepseek-coder-v2:16b` (8.9 GB) — не помещается.

## 2. Настройка (что лежит в репо)

| Файл | Что |
|---|---|
| `.continue/models/local-ollama.yaml` | модели, роли (`chat/edit/apply/autocomplete`), `temperature 0.2`, `topP 0.9`, `contextLength 16384`, `maxTokens 2048`; автокомплит: `debounceDelay 350`, `maxPromptTokens 1024`, `modelTimeout 5000` |
| `.continue/rules/01-mexamen.md` | **правила из Дня 1** (= `CLAUDE.md` v2, `alwaysApply: true`) → системный промпт. Копия, не symlink; обновлять: `{ printf -- '---\nname: Mexamen project rules (CLAUDE.md v2)\nalwaysApply: true\n---\n\n'; cat CLAUDE.md; } > .continue/rules/01-mexamen.md` |
| `.continue/context/mexamen-context.yaml` | что модель видит: `@File @Folder @Code @CurrentFile @Open(pinned) @Diff @Terminal @Problems @Tree`; **без `@Codebase`** |
| `.continueignore` | исключены данные/логи (`questions.json` ×2 по 0.5 MB, `*.jsonl`, `tools/`, `docs/`, `smoke/`, ресурсы) |
| `docs/local-llm/rules-compact.md` | сжатые правила (~0.5k ток. вместо ~3.8k) для «лучшей связки» |
| `docs/local-llm/Modelfile.qwen2.5-3b-mexamen` | параметры лучшей связки |
| `docs/local-llm/bench.py`, `bench-results.txt` | замер скорости (stdlib), сырые результаты |
| `docs/local-llm/runs.md`, `logs/` | журнал прогонов, сессии Continue (JSON), diff'ы |

Cursor: выключен Cursor Tab (конфликт с автокомплитом Continue); `continue.pauseCodebaseIndexOnStart: true` в user settings. `Ctrl+I` в Cursor занят своим агентом → Continue Edit через ПКМ → *Continue → Add to Edit*.

**Контекст — почему без индекса:** эмбеддинг-индекс `@Codebase` на `nomic-embed-text` грузил 4 ядра >85 мин (эмбеддил JSON-данные) и вдвое замедлял инференс (prefill 18 → 36.5 ток/с после отключения). На CPU индекс и генерация не уживаются; контекст подаётся явно через `@File`.

**Бюджет токенов:** полный `CLAUDE.md` = 3 791 токенов (Qwen-токенайзер). Агентный режим Continue добавляет системный промпт с описанием tools, + поданные файлы → ~10k. Поэтому `contextLength` 16k (KV-кэш 3B ≈ 37 KB/ток → 0.6 GB), для лучшей связки — 8k + compact rules.

| `qwen3:4b` (thinking) | 12.6 ток/с | 1.9 ток/с | 301 с | **1 187 с** | лучший: §5.①, «один тип на файл» |

Автокомплит `coder:1.5b`: **~2.8 с** на тёплой модели (холодный старт 6.7 с); на тесте FIM дописал тело функции, но с ошибкой типа (`Double` в `Int`-функции).

Вывод по скорости: **полный файл правил стоит 1.5–3.5 мин ожидания перед первым токеном** каждого нового чата (Ollama кэширует префикс — внутри одного чата дальше быстрее). Сжатые правила — главный рычаг скорости на CPU.

## 5. Облачный ассистент vs локальная модель

Облако: Claude Code, те же задачи — `docs/rules-experiment/README.md` (День 1), `docs/profiles/README.md` (День 2). Локальная — лучший результат из прогонов выше.

| Критерий | Облако (Claude Code) | Локальная (Ollama + Continue, 1.5–3B, CPU) |
|---|---|---|
| **День 1 (фича, 9 файлов)** | ✅ с 1-го раза: компилируется, тесты зелёные + новые тесты, логика в `domain/`, учтена гонка записи; +139/−16 | ❌ 0 строк кода, только текст с выдуманными путями и русским UI |
| **День 2 (агент Bug Fix)** | ✅ 52–125 с, 14–16 ходов, сам нашёл файл, сам прогнал `compileAndroidMain` + wasm + тесты | ❌ в Agent — 3 провала из 3 (не тот файл / поломка / зацикливание); 🟡 в Edit с выделенным кодом — почти, 2 ошибки компиляции |
| **Качество кода** | соответствует правилам (слои, stateless Screen, испанский, Koin) | нарушает правила, которые видит в промпте (`R.string`, `Icons.Default`, `LocalContext`, русский текст); копирует слова правил без смысла |
| **Скорость** | секунды на ход; задача целиком 1–2 мин | автокомплит ~3 с; Edit 2 мин; чат 2–4 мин до первого токена с полными правилами; агент 5–26 мин и без результата |
| **Понимание контекста проекта** | читает файлы сам, ориентируется по существующему коду | сама файлы не открывает; с поданным `@File` находит место, но не удерживает структуру при ~10k токенов |
| **Агентный режим / tool calling** | надёжный, многошаговый, с самопроверкой | 3B: 0–1 вызов, без чтения перед правкой; 1.5B: tool calling только текстом |
| **Честность отчёта** | говорит, что проверено и что нет | заявляет «готово» без сборки |
| **Работа без интернета** | ❌ | ✅ полностью офлайн, код не уходит наружу, $0 за токены |
| **Ресурсы ноутбука** | ~0 | 2–5 GB RAM, все ядра CPU; рядом с Gradle — swap |
| **Стоимость** | ~$0.12 за прогон Дня 2 | 0, но время разработчика |

## 6. Лучшая связка на этом железе

**`qwen2.5:3b` + `repeat_penalty 1.15` / `repeat_last_n 256` + `temperature 0.2` / `top_p 0.9` + `num_ctx 8192` + сжатые правила (~0.5k ток.) + режим Edit с выделенным кодом**, и `qwen2.5-coder:1.5b` на автокомплите (`temperature 0.1`, `maxPromptTokens 1024`).

Что дал каждый рычаг (по прогонам 3 → 4):
- **Режим Edit вместо Agent** — главное: модель не ищет файлы и не вызывает tools, правит только выделенное. Время 13–26 мин → 2 мин.
- **Сжатые правила** — prefill 3.8k → ~0.5k ток.: минуты ожидания → секунды; правила короче — меньше «копирования слов».
- **`repeat_penalty`** — убрал вырожденный повтор (прогон 3).
- **Конкретный промпт** (что убрать / что добавить / какой `AppIcons.X` / куда) — без него 3B не знает API проекта.
- **Не помогло:** больше контекста (16k + поданные файлы → зацикливание), большая модель (`qwen3:4b` в 5× медленнее — неприменима в интерактиве).

## 7. Рекомендация: для чего хватает локальной

**Хватает (локальная 1.5–3B на CPU):**
- автокомплит строки/блока, бойлерплейт, импорты, повторяющиеся конструкции — подсказку проверяешь глазами за секунду;
- точечная правка **выделенного** кода по конкретной инструкции (Edit), с ручной доводкой и сборкой человеком;
- вопросы «что делает эта функция», «где это правило» по поданному `@File`; объяснение ошибки компилятора;
- работа без сети / с кодом, который нельзя отправлять наружу.

**Облако незаменимо:**
- фича через несколько слоёв (День 1: store → domain → VM → UI → DI → тест);
- агентный режим: самостоятельный поиск файлов, правка, запуск сборки/тестов, исправление по ошибкам (День 2);
- соблюдение длинного свода правил проекта (CLAUDE.md 15 KB) и учёт неочевидного (гонка асинхронной записи);
- всё, где нужен честный отчёт «что проверено» — локальная 3B заявляет успех без проверки.

**Порог:** на этом ноутбуке локальная модель — **автокомплит и «умный Edit»**, но не ассистент-агент. Чтобы локально приблизиться к облаку на агентных задачах, нужно ≥14–32B coder-модель с надёжным tool calling, т.е. дискретная GPU с 12–24 GB VRAM или 32+ GB RAM.

## Воспроизвести

```bash
sudo snap start ollama
ollama pull qwen2.5-coder:1.5b; ollama pull qwen2.5:3b
ollama create qwen2.5-3b-mexamen -f docs/local-llm/Modelfile.qwen2.5-3b-mexamen
cursor --install-extension Continue.continue   # затем Cursor Settings → Tab → off
python3 docs/local-llm/bench.py qwen2.5-coder:1.5b qwen2.5:3b
# задачи и промпты: docs/local-llm/tasks.md; worktree от 2ba764c (День 1) и c1aae01 (День 2)
```
