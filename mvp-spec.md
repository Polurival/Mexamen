# Mexamen — Спецификация (spec.md)

> Документ Specification-Driven Development. Источник истины о том, **что** мы строим и **зачем**. Реализация следует этому файлу и `plan.md`. Кода здесь нет.

---

## 1. Обзор проекта

**Mexamen** — Android-приложение (Compose Multiplatform, Kotlin) для подготовки к экзамену на натурализацию в Мексике (получение мексиканского гражданства через SRE). Экзамен сдаётся на испанском языке и покрывает историю, географию, культуру и государственное устройство Мексики.

**Решаемая задача.** Официальный гид для подготовки — это сотни вопросов с ответами в виде сплошного текста (источник: https://ruspansky.com/guia-de-estudios/, ~800 пар «вопрос → ответ» в 13 тематических разделах). Готовиться по такому списку неудобно: нет самопроверки, нет формата «выбери правильный ответ», как на реальном экзамене. Mexamen превращает этот материал в интерактивный квиз.

**Как участвует AI.** У вопросов из гида есть только правильный ответ — вариантов «неправильных» ответов не существует. LLM генерирует **3 правдоподобных дистрактора** (неверных варианта) для каждого вопроса. Чтобы дистракторы были правдоподобными (например, для вопроса о столице штата — столицы других штатов, а не случайные слова), используется **RAG**: перед генерацией из локальной векторной базы извлекаются семантически похожие пары «вопрос → ответ», и их ответы подаются модели как контекст.

**MVP-scope:** только Android-таргет Compose Multiplatform, один режим — квиз из 10 вопросов, испанский язык, без авторизации.

## 2. Цели

- Рабочее Android-приложение: квиз из 10 случайных вопросов, по 4 варианта ответа (1 верный + 3 сгенерированных LLM).
- **RAG-пайплайн своими руками**: локальная база вопросов/ответов с precomputed-эмбеддингами, косинусный поиск top-K на устройстве, без сторонних vector-DB и LLM-фреймворков.
- **LLM через абстракцию**: интерфейс `LlmProvider`; MVP-реализация — DeepSeek API (ключ есть). Замена на Gemini free tier или on-device Gemma (LiteRT-LM) — без переделки остального кода.
- **Graceful degradation**: при недоступности LLM (нет сети / нет ключа / ошибка API) квиз всё равно работает — дистракторы берутся из ответов ближайших RAG-соседей.
- Оффлайн-пайплайн подготовки данных: скрейпинг гида → датасет → эмбеддинги → ассеты приложения.
- Простой UI по гайдлайнам Material 3.
- Читаемый, модульный, тестируемый идиоматичный Kotlin на корутинах; бизнес-логика в `commonMain` (готовность к iOS/Desktop в будущем).

## 3. Не-цели (MVP)

- Нет iOS/Desktop/Web-таргетов (структура CMP-проекта их допускает, но не собираем).
- Нет авторизации, аккаунтов, бэкенда — приложение полностью client-side.
- Нет on-device LLM в MVP (решение зафиксировано в §8; интерфейс оставляет дверь открытой).
- Нет runtime-эмбеддинга запросов на устройстве — эмбеддинги считаются только оффлайн, на устройстве только косинусный поиск по готовым векторам.
- Нет перевода на русский/английский — квиз только на испанском (как реальный экзамен).
- Нет статистики прогресса, spaced repetition, выбора разделов — только «быстрый квиз на 10 вопросов».
- Нет публикации в Google Play.

## 4. Функциональные требования

- **FR-1 — Датасет.** В ассеты приложения включена база из ~800 пар «вопрос → ответ» (13 разделов гида), полученная оффлайн-скрейпингом https://ruspansky.com/guia-de-estudios/. Формат: `questions.json` (id, раздел, вопрос, ответ) + `embeddings.bin` (float32-векторы, выровнены по id).
- **FR-2 — Выбор вопросов.** При старте квиза выбираются 10 случайных вопросов, равномерно распределённых по разделам (не более 2 из одного раздела, при возможности).
- **FR-3 — RAG-извлечение.** Для каждого выбранного вопроса из векторной базы извлекаются top-K (K=8) семантически ближайших пар «вопрос → ответ» (сам вопрос исключается) по косинусной близости.
- **FR-4 — Генерация дистракторов.** Один запрос к LLM на весь квиз (батч из 10 вопросов): для каждого вопроса модель получает вопрос, правильный ответ и RAG-контекст и возвращает ровно 3 неверных, но правдоподобных варианта на испанском. Ответ модели — строгий JSON.
- **FR-5 — Валидация ответа LLM.** Ответ парсится и валидируется: 3 дистрактора на вопрос, ни один не совпадает (case/accent-insensitive) с правильным ответом и друг с другом. Невалидные элементы заменяются fallback-дистракторами (FR-6).
- **FR-6 — Fallback без LLM.** При любой ошибке LLM (сеть, таймаут 30 с, невалидный JSON, нет ключа) дистракторы для вопроса — это ответы 3 ближайших RAG-соседей. Квиз никогда не блокируется из-за LLM.
- **FR-7 — Прохождение квиза.** Экран вопроса: текст вопроса, номер (n/10), 4 перемешанных варианта. После выбора — мгновенная подсветка верного/неверного, затем переход к следующему вопросу.
- **FR-8 — Результат.** Экран результата: счёт X/10, список вопросов с пометкой верно/неверно и правильным ответом, кнопка «пройти ещё раз» (новые 10 вопросов, новая генерация).
- **FR-9 — Индикация источника вариантов.** Если использовался fallback (FR-6), UI ненавязчиво показывает оффлайн-режим (иконка/подпись), чтобы поведение было объяснимым.
- **FR-10 — Оффлайн-пайплайн данных.** Отдельный инструмент (не приложение) скрейпит гид, чистит данные, считает эмбеддинги через локальный Ollama (`nomic-embed-text`, 768-dim) и записывает `questions.json` + `embeddings.bin` в ассеты. Запускается вручную на машине разработчика; результат коммитится.

## 5. Нефункциональные требования

- **NFR-1 — Время старта квиза.** Плейсхолдер-прогресс во время генерации; при ошибке/таймауте (30 с) — мгновенный fallback. Пользователь ждёт не дольше 30 с в худшем случае.
- **NFR-2 — Память.** Векторная база (~800 × 768 float32 ≈ 2.4 MB) загружается в память один раз лениво; косинусный top-K по 800 векторам — миллисекунды, без индексов.
- **NFR-3 — Секреты.** API-ключ DeepSeek не хранится в git: `local.properties` → `BuildConfig`. Приложение корректно работает без ключа (fallback-режим).
- **NFR-4 — Стоимость.** ~1 запрос DeepSeek на квиз (≈2–4 K токенов) — доли цента. Лимитов/биллинга в приложении нет.
- **NFR-5 — Тестируемость.** Выбор вопросов, retrieval, сборка промпта, парсинг/валидация ответа LLM, fallback — чистые функции/классы в `commonMain`, покрыты unit-тестами без Android-зависимостей.
- **NFR-6 — UI.** Material 3 (динамическая цветовая схема Android 12+, светлая/тёмная тема из коробки), поддержка экранов от 5", портретная ориентация.

## 6. Архитектура

```
┌────────────────────────── Оффлайн (машина разработчика) ──────────────────────────┐
│  tools/scraper  ──►  guia_raw.html  ──►  questions.json  ──►  Ollama nomic-embed  │
│                                                              ──►  embeddings.bin  │
└──────────────────────────────────────┬────────────────────────────────────────────┘
                                       │  commit в composeApp/src/.../assets
┌──────────────────────────── Приложение (Android) ────────────▼────────────────────┐
│  UI (Compose M3)          Domain (commonMain)               Data (commonMain)     │
│  HomeScreen        ◄────  QuizViewModel                                           │
│  QuizScreen               └─ StartQuizUseCase ──► QuestionRepository (json+bin)   │
│  ResultScreen                  │                  VectorStore (cosine top-K)      │
│                                └──► DistractorGenerator                           │
│                                       ├─ LlmProvider (interface)                  │
│                                       │    └─ DeepSeekProvider (Ktor, chat API)   │
│                                       └─ RagFallback (ответы соседей)             │
└───────────────────────────────────────────────────────────────────────────────────┘
```

**Поток данных при старте квиза:**
1. `StartQuizUseCase`: 10 случайных вопросов (FR-2).
2. `VectorStore`: для каждого — top-8 соседей (FR-3).
3. `DistractorGenerator` собирает один батч-промпт → `LlmProvider.complete()` (FR-4).
4. Парсинг + валидация (FR-5); дыры закрываются `RagFallback` (FR-6).
5. `QuizViewModel` отдаёт UI готовый список из 10 `QuizQuestion` (вопрос + 4 перемешанных варианта + индекс верного).

### Модель данных

```
QuestionEntry(id: Int, section: String, question: String, answer: String)
QuizQuestion(entry: QuestionEntry, options: List<String>, correctIndex: Int, source: LLM | FALLBACK)
QuizResult(answers: List<Pair<QuizQuestion, chosenIndex>>, score: Int)
```

### Контракт LLM (FR-4)

Запрос: system-промпт (роль: составитель экзамена, испанский, JSON-only) + JSON-массив из 10 объектов `{id, question, correct_answer, context: [похожие ответы]}`.
Ответ: `{"items":[{"id":1,"distractors":["...","...","..."]}, ...]}` — парсится kotlinx.serialization, невалидное отбрасывается поэлементно.

| Слой | Выбор | Почему |
|---|---|---|
| Проект | Compose Multiplatform (таргет: Android), Kotlin 2.x | Требование задачи; логика в `commonMain` — задел на iOS |

| Эмбеддинги (оффлайн) | Ollama `nomic-embed-text` (768-dim) | Локально, бесплатно; паттерн из `week_5_RAG/embedder.py` |
| Скрейпер | Python (requests + BeautifulSoup) в `tools/` | Одноразовый инструмент, быстрее всего |
| Тесты | kotlin-test, JUnit, Ktor MockEngine | Unit-тесты domain-слоя |

## 8. Решение по LLM (исследование)

Рассмотрены варианты генерации дистракторов на мобильном устройстве:

| Вариант | Бесплатно | Вердикт |
|---|---|---|
| ML Kit GenAI / Gemini Nano (AICore) | да, on-device | Только Pixel и флагманы — слишком узко для MVP |
| On-device Gemma 3n E2B (MediaPipe LLM Inference → LiteRT-LM) | да | 1.5–3 GB загрузка модели, медленный CPU-инференс, риск качества испанских дистракторов; MediaPipe LLM API переведён в maintenance-режим. Слишком тяжело для MVP |
| Gemini API free tier (`gemini-2.5-flash-lite`) | да, ~1000 req/день | Лучший бесплатный вариант; требует новый ключ |
| **DeepSeek API (выбран)** | нет (~$0.0002/квиз) | Ключ уже есть, качественный испанский, строгий JSON. **MVP-выбор** |

**Решение:** удалённый LLM через интерфейс `LlmProvider`; MVP — DeepSeek. Второй провайдер (Gemini free / on-device) — post-MVP, добавляется реализацией одного интерфейса. При отсутствии LLM приложение остаётся рабочим (FR-6).

## 10. Критерии приёмки MVP

1. `./gradlew :composeApp:assembleDebug` собирает APK; приложение ставится и запускается на устройстве/эмуляторе (Android 8.0+, API 26).
2. Квиз: 10 вопросов × 4 варианта; с валидным ключом DeepSeek ≥ 8 из 10 вопросов получают LLM-дистракторы (остальные — fallback).
3. В авиарежиме квиз запускается и полностью проходится (fallback-дистракторы, индикатор оффлайн).
4. Экран результатов показывает счёт и разбор ошибок; повторный запуск даёт другой набор вопросов.
5. Unit-тесты (retrieval, промпт, парсинг, валидация, fallback) зелёные: `./gradlew :composeApp:testDebugUnitTest`.
6. README объясняет задачу, роль AI (LLM + RAG), запуск пайплайна данных и сборку приложения.
