# Mexamen — План: реальные варианты ответов из test-1..test-10 (post-MVP)

> Компаньон `mvp-plan.md`, тот же формат. Источник: https://ruspansky.com/test-1/ … `/test-10/` (WATU-quiz плагин, 740 вопросов-инстансов, 656 из 776 вопросов `questions.json` найдены по тексту).

**Идея.** Test-страницы содержат по 4 варианта ответа на вопрос, но не помечают верный в HTML (грейдинг server-side). Верный вариант вычисляется сопоставлением с уже известным `answer` из `questions.json`; оставшиеся 3 — реальные, человеком написанные неверные варианты. Они:
1. Используются как реальные дистракторы (приоритет над текущим `RagFallback` на основе ответов соседей).
2. Передаются в LLM как контекст-примеры «неверных ответов в таком стиле» вместо текущего контекста (ответы RAG-соседей) — LLM генерирует 3 новых, похожих по духу, для вариативности при повторном прохождении.
3. Формулировка верного варианта на test-странице иногда отличается от `answer` в датасете (перефразировка) — это фиксируется как альтернативная формулировка того же правильного ответа: `answerVariants`, случайный выбор одного при сборке квиза.

**LLM как и раньше генерирует только неверные варианты — этот принцип не меняется.**

Проверено вручную (эта сессия): 656/776 вопросов смэтчены по тексту; из них 498 — точное совпадение ответа среди 4 опций, 104 — по подстроке, 54 — неоднозначны (нужна ручная разметка); 120 вопросов на test-страницах не найдены вовсе (для них — прежний путь: LLM + старый `RagFallback`).

## Фаза F — Данные

### Задача F1 — Скрипт сопоставления test-страниц с questions.json
- **Цель:** `tools/match_real_answers.py` дополняет `questions.json` полями `answerVariants` и `realDistractors`.
- **Описание:** Скачать (или взять из кэша) test-1..test-10 (тот же User-Agent, что в `scrape_guia.py` — Cloudflare/ModSecurity блокирует запросы без него). Распарсить WATU-блоки (`div.watu-question` → текст вопроса + `span.answer` × 4). Сматчить вопрос с `questions.json` по нормализованному тексту (NFKD, без диакритики, lower, схлопнутые не-alnum). Для сматченных — определить верный вариант: exact/substring сравнение с `answer`; однозначные (~602) — automatически, оставшиеся 3 варианта → `realDistractors`; неоднозначные (~54, когда 0 или ≥2 варианта совпали по подстроке) — выгрузить в `tools/out/match_review.json` для ручной разметки (не гадать эвристикой). Формулировка верного варианта, если отличается от `answer`, добавляется в `answerVariants`.
- **Файлы:** `tools/match_real_answers.py`, `tools/out/test_pages_cache/test-{1..10}.html` (кэш), `tools/out/match_review.json`, обновлённый `tools/out/questions.json`.
- **Зависимости:** нет.
- **DoD:** ≥600 вопросов получили `realDistractors` (ровно 3, уникальных, не совпадающих с `answer`) автоматически; `match_review.json` содержит все неоднозначные случаи с обоими текстами (dataset answer + 4 опции) для ручной сверки.
- **Проверка:** `python tools/match_real_answers.py`; спот-чек 10 случайных вопросов с `realDistractors` вручную сверить с соответствующей test-страницей.

### Задача F2 — Ручная разметка review-списка
- **Цель:** закрыть ~54 неоднозначных вопроса.
- **Описание:** Руками пройти `match_review.json`, указать индекс верного варианта для каждого; перезапустить F1 с разметкой (или отдельный merge-шаг), получить финальный `questions.json`.
- **Файлы:** `tools/out/match_review.json` (заполнено), финальный `tools/out/questions.json`.
- **Зависимости:** F1.
- **DoD:** 0 записей без разметки в `match_review.json`; итоговое покрытие (сколько вопросов с `realDistractors`, сколько только с `answerVariants`, сколько без ни того ни другого) зафиксировано в README.
- **Проверка:** глазами — ревью diff `questions.json`.

## Фаза G — Domain: используем реальные данные

### Задача G1 — Схема данных: QuestionEntry
- **Цель:** приложение читает `answerVariants` и `realDistractors`.
- **Описание:** `QuestionEntry` расширяется (kotlinx.serialization): `answerVariants: List<String>` (минимум один элемент — старый `answer`), `realDistractors: List<String> = emptyList()`. Обратная совместимость — дефолты, старые записи без новых полей не ломаются.
- **Файлы:** `…/data/QuestionEntry.kt`, `…/data/QuestionRepository.kt`, `QuestionRepositoryTest`.
- **Зависимости:** F2.
- **DoD:** тест: все записи парсятся, `answerVariants` непусто у каждой; существующие тесты (45) не сломаны.
- **Проверка:** `./gradlew :composeApp:testDebugUnitTest`.

### Задача G2 — BuildQuizUseCase: случайный выбор верного варианта
- **Цель:** отображаемый верный ответ — случайный элемент `answerVariants`.
- **Описание:** `BuildQuizUseCase` берёт `answerVariants.random(rng)` (инжектируемый `Random`, как и `QuestionPicker`). Дедуп дистракторов сверяется со **всеми** `answerVariants`, а не только с выбранным.
- **Файлы:** `…/domain/BuildQuizUseCase.kt`, тесты (seed-тест на детерминированность выбора).
- **Зависимости:** G1.
- **DoD:** тест: выбор варианта детерминирован при фиксированном seed; дистракторы никогда не совпадают ни с одним из `answerVariants`.
- **Проверка:** тесты зелёные.

### Задача G3 — RagFallback: приоритет realDistractors
- **Цель:** без LLM дистракторы берутся в порядке: свои `realDistractors` → соседские `realDistractors` → старое поведение (ответы соседей).
- **Описание:** `RagFallback.distractors(entry, neighbors)`: 1) `entry.realDistractors`, дедуп/паддинг до 3; 2) добор из `neighbors[].realDistractors`; 3) добор из `neighbors[].answerVariants` (текущий FR-6), пока не наберётся 3 уникальных.
- **Файлы:** `…/domain/RagFallback.kt`, тесты (3 сценария: только real, real+сосед, совсем нет real).
- **Зависимости:** G2.
- **DoD:** тесты покрывают все 3 сценария приоритета; на выходе всегда ровно 3 уникальных дистрактора, не пересекающихся с `answerVariants`.
- **Проверка:** тесты зелёные.

## Фаза H — LLM: реальные дистракторы как контекст

### Задача H1 — PromptBuilder: контекст из реальных неверных ответов
- **Цель:** FR-4 меняется — контекст для LLM это `realDistractors` (свои + соседские), а не ответы соседей.
- **Описание:** `PromptBuilder` собирает per-question context = `entry.realDistractors`, при нехватке добирает из `neighbors[].realDistractors`; если рядом нигде нет `realDistractors` — fallback на старый контекст (ответы соседей, текущее поведение), чтобы не терять качество для непокрытых вопросов. System-промпт: «вот примеры неверных ответов на похожие вопросы, сгенерируй 3 новых в этом стиле, не совпадающих с примерами и с верным ответом».
- **Файлы:** `…/llm/PromptBuilder.kt`, тесты (промпт с real-контекстом / промпт со старым fallback-контекстом).
- **Зависимости:** G3.
- **DoD:** тест: собранный промпт содержит `realDistractors`, когда они есть у вопроса или соседей; иначе — старый neighbor-context.
- **Проверка:** тесты зелёные.

### Задача H2 — Валидация ответа LLM: дедуп против answerVariants и примеров
- **Цель:** FR-5 расширяется на новые поля.
- **Описание:** `DistractorGenerator` — LLM-дистрактор невалиден, если совпадает (case/accent-insensitive) с любым из `answerVariants` ИЛИ с любым из переданных `realDistractors`-примеров (LLM не должен повторить пример как «новый»). Невалидные заменяются через `RagFallback` (G3).
- **Файлы:** `…/llm/DistractorGenerator.kt`, тесты (4 старых сценария FR-5 + 2 новых: LLM повторил real-пример; LLM попал в альтернативный correct-вариант).
- **Зависимости:** H1.
- **DoD:** все тесты валидации зелёные, включая новые кейсы.
- **Проверка:** тесты + ручной прогон с реальным ключом — спот-чек 10 вопросов, дистракторы правдоподобны и не дублируют примеры/верные варианты.
